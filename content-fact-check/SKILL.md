# 内容事实核查

## 触发条件

- 用户给出草稿（全文或片段），要求「核查」「验证」「看看有没有问题」
- 用户转述了一条热点帖子的数字/结论，想确认能不能写进文章

## 核心方法

### 1. 提取可疑论断

扫描全文，标记四类论断：具体数字（价格、规格、时间）、绝对化表述（最低、第一、唯一）、因果断言（X 导致 Y）、转述引用（据说、网传、有人实测）。

### 2. 逐项对官方原始出处

把每个数字和说法与官方定价页、官方文档、政策原文逐一对上，精确到分。对上了的也要标注口径：
- 价格是活动价还是原价
- 对比基准是高峰价还是空闲价
- 积分/额度是否结转或退款
- 是否限新用户或特定地区

### 3. 挖隐藏条款

逐条读官方订阅须知、使用限制，重点看「严禁」「仅限」「不保证」字样。这一步最常挖出差异化素材：全网都在转的帖子往往漏掉最关键的条款。

### 4. 结论分层

核查结论只用三档：属实（附出处）、部分属实（说明哪部分对哪部分错）、无出处（建议删除或改为可验证表述）。不要用「真假」二选一。

## 输出格式

```
论断 1：「0.1 元买 5000 万 token，全网最低」
结论：部分属实
出处：官网活动页（链接）
说明：数字与活动页一致，口径为活动价；「全网最低」无出处，建议删除或改为「官方渠道目前最低」
修改建议：「0.1 元买 5000 万 token（活动价）」
隐藏条款：需核对积分是否结转、是否限新用户
```

## 纪律

- 只认官方原始出处，二手转述帖不能作为出处
- 单一来源要标注「单源」，多源交叉验证后才标「已验证」
- 核查报告是建议不是判决，定稿权在用户
- 检验标准：读者只看官方文档，能不能验证文中每个数字？不能验证的要补出处或删掉
